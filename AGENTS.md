# Working on polyvisor

This is an unstable, exploratory project with **no users**. Optimize for
learning and cheap revision; complexity and maintenance cost need a
present justification. Existing code, tests, and documentation are
revisable choices, not evidence of a user requirement.

Read `docs/design.md`, especially **Project maturity and tradeoffs**,
before implementation. That section governs compatibility, scope, and
testing choices. Include this maturity constraint in coder/reviewer
dispatches; do not pass down only the feature requirements and gates.
